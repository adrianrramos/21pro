Homebrew installation for macOS

Status: Deferred. No Homebrew packaging has been implemented.

Goal: Install 21 Pro as a Finder-launchable app without requiring users to install Rust or compile the project.

Proposed approach: Distribute prebuilt macOS releases through a Homebrew cask in a project-owned tap. Inclusion in Homebrew’s official repositories is not required.

Remaining work

  • Build and verify macOS app bundles for Apple Silicon and Intel, using separate archives or a universal app.
  • Set up signing and notarization for public distribution.
  • Publish versioned ZIP or DMG assets on GitHub Releases.
  • Create a Homebrew tap and cask with release URLs, SHA-256 checksums, and the supported macOS version.
  • Verify installation, launching, upgrades, and uninstallation on macOS.
  • Document the published installation commands in the README.

Current starting point: The repository contains app-bundle metadata and local build instructions. The README records macOS launching, bundling, and signing/notarization as unverified.

Reference: Homebrew Cask Cookbook.

Optional hand-value display

Status: Planned. Add a setting that controls whether the current hand value is shown.

Goal: When hand values are hidden, require the user to total the cards mentally instead of relying on the software's calculation.

Acceptance intent

  • Users can turn the hand-value display on or off before or during practice.
  • When disabled, no hand value is shown anywhere in the active practice view.
  • Re-enabling the setting restores the normal hand-value display.

Focused hand-type practice

Status: Planned. Let users focus practice on specific hand types instead of receiving an unrestricted mix.

Goal: Support targeted practice such as soft hands, splits, doubles, and other hand categories as they are added.

Acceptance intent

  • Users can select one or more hand types to practice.
  • Dealt scenarios respect the selected hand-type focus.
  • Focused practice results are recorded in the user's playing history with the relevant hand type.

Running-count checks

Status: Planned. Periodically test whether the user is maintaining the running count accurately during play.

Goal: After every 10–15 hands, prompt the user to enter the running count and verify the answer against the correct count.

Acceptance intent

  • The software prompts for the running count at 10–15-hand intervals during a counting session.
  • Each response is marked correct or incorrect against the actual running count.
  • Running-count accuracy is recorded as a new insight metric for the user's progress.
